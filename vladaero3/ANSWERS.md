# ✈️ Все 280 вопросов и точных ответов проекта «VladAero»

> **Брендинг, айдентика и подготовка к разработке:**
> - **Название проекта:** **VladAero**
> - **Логотип:** Готовый PNG-логотип в наличии (будет размещен в `assets/images/logo.png` / подключается через мастер установки и админ-панель).
> - **Обязательное предварительное исследование перед разработкой (Pre-development Research):** Перед началом кодинга и созданием архитектуры обязательно произвести поиск в интернете на предмет доступных бесплатных и публичных API:
>   1. **Онлайн-табло аэропортов (FIDS / Flight Information Display Systems):** бесплатные API расписания рейсов, фактических статусов прилета/вылета, задержек и гейтов.
>   2. **Живые веб-камеры и видеотрансляции авиации:** бесплатные/публичные стримы (HLS, RTMP, YouTube Live, IP-камеры) с взлетно-посадочных полос, перронов и споттинг-локаций мировых аэропортов.
>   3. **Радиообмен диспетчеров (LiveATC):** потоки и стримы каналов УВД (TWR, GND, APP, CTR) для плеера.
>   4. **Радар и ADS-B трекинг:** бесплатные эндпоинты (OpenSky Network, ADS-B One, FlightRadar community feeds) для отображения бортов в реальном времени.
>   5. **Авиационная погода:** бесплатные парсеры и API сводок METAR, прогнозов TAF и оповещений NOTAM.
> - **Требования к ИИ-агентам и виджетам:**
>   - **Пользовательский AI-виджет:** минимум 20 нативных встроенных инструментов (включая веб-поиск Firecrawl Web Search и парсинг страниц Firecrawl Fetch URL).
>   - **AI Супер-Агент в панели администратора:** минимум 50 инструментов (управление контентом, самодиагностика БД System Self-Healing, пакетная генерация, аудит логов, управление кэшем, медиа и Cron).
>   - **Стриминг в реальном времени:** повсеместный Realtime SSE Streaming для всех ответов ИИ, а при использовании reasoning-моделей — обязательный real-time стриминг цепочки рассуждений (Reasoning block stream).

### Блок 1 (Вопросы 1–5)
1. **Какова главная цель и ключевой формат вашего авиационного сайта?**
   - **Ответ:** вообще все из этого кроме коммерческого (проект называется VladAero, есть готовый PNG-логотип)

2. **Кто является вашей основной целевой аудиторией?**
   - **Ответ:** Любители авиации, энтузиасты и споттеры, Профессионалы отрасли (пилоты, бортпроводники, инженеры, диспетчеры), Симмеры и фанаты авиасимуляторов (MSFS, X-Plane, DCS), Пассажиры и путешественники (отзывы об авиакомпаниях, советы по перелетам)

3. **Какие направления авиации будут представлены на сайте?**
   - **Ответ:** Гражданская и коммерческая авиация (пассажирские лайнеры, авиакомпании, аэропорты), Военная авиация (боевые самолёты, вертолёты, история), Малая авиация и АОН (частные самолёты, сверхлёгкая авиация, вертолёты), Историческая и ретро-авиация (самолёты Первой и Второй мировых войн, музейные экспонаты), Беспилотная авиация (БПЛА, дроны, перспективные технологии)

4. **Какой интерактивный и мультимедийный функционал планируется?**
   - **Ответ:** (Recommended) Фотогалерея со споттингом и карточками бортов (бортовой номер, авиакомпания, фото), Интерактивный радар / трекинг рейсов (интеграция с трекерами или собственный трекер), Инструмент сравнения самолётов по ТТХ и параметрам, Календарь авиационных событий (авиашоу, выставки, споттинг-сессии), Интерактивные 3D-модели или виртуальные кабины самолётов

5. **Требуется ли регистрация пользователей и личные кабинеты на сайте?**
   - **Ответ:** Да, с возможностью вести свой блог, загружать споттерские фото и общаться в клубах

### Блок 2 (Вопросы 6–10)
6. **[Вопрос 6/150] Какие блоки информации обязательно должны быть на странице карточки каждого самолёта?**
   - **Ответ:** ТТХ и летные данные (скорость, дальность, потолок, размеры), Модификации и варианты самолета, История создания, боевого применения и эксплуатации, Галерея фотографий конкретной модели и ливреи авиакомпаний, Интерактивная 3D-модель / схема салона и кабины (cockpit view), Список происшествий и безопасность (safety record)

7. **[Вопрос 7/150] Какой уровень детализации характеристик (ТТХ) должен быть в базе данных?**
   - **Ответ:** Двухуровневый вид: простая сводка для обычных пользователей + подробная вкладка с инженерными ТТХ для профи/симмеров

8. **[Вопрос 8/150] Какие варианты поиска и фильтрации нужны в каталоге авиатехники?**
   - **Ответ:** Фильтры по ТТХ (дальность полета, скорость, пассажировместимость, число двигателей), Фильтры по классификации (страна, производитель, поколение, эпоха/годы выпуска, военный/гражданский), Поиск по кодам ICAO/IATA и бортовым номерам (Tail numbers), Визуальный выбор по силуэтам / типам конструкции (моноплан, биплан, схема «утка» и т.д.)

9. **[Вопрос 9/150] Каким способом планируется первично и регулярно наполнять базу данных и статьи?**
   - **Ответ:** Краудсорсинг / Вики-модель: пользователи предлагают правки и новые статьи, модераторы одобряют, Импорт / парсинг открытых реестров и баз данных (реестры ВС, авиационные справочники), ИИ-интеграция для первичного сбора ТТХ и описаний с обязательной проверкой редакторами, Эксклюзивные авторские материалы и статьи штатной редакции / экспертов

10. **[Вопрос 10/150] Нужны ли отдельные разделы для Авиакомпаний и Аэропортов?**
    - **Ответ:** Да, полноценные каталоги: Авиакомпании (парк флота, ливреи) и Аэропорты (коды ICAO/IATA, полосы, схемы, погода METAR/TAF)

### Блок 3 (Вопросы 11–15)
11. **[Вопрос 11/150] Как должен быть организован процесс публикации и проверки фотографий споттеров?**
    - **Ответ:** Гибридная модель: новички проходят премодерацию (скрининг качества), а проверенные споттеры публикуют сразу

12. **[Вопрос 12/150] Какие метаданные должны автоматически или вручную привязываться к каждому фото?**
    - **Ответ:** Бортовой номер (Регистрация / Tail number) и серийный номер (MSN / CN), Авиакомпания (эксплуатант) и специальная ливрея, Аэропорт / локация споттинга (с геопривязкой на карте), Параметры съемки из EXIF (камера, объектив, фокусное расстояние, выдержка, ISO, диафрагма), Дата съемки и статус борта на момент фото (действующий, на хранении, списан)

13. **[Вопрос 13/150] Какие механизмы защиты авторских прав и прав использования фотографий требуются?**
    - **Ответ:** Автоматическое наложение водяного знака (watermark) с именем автора и логотипом портала, Выбор лицензии автором (All rights reserved, Creative Commons, свободное использование), Функция запроса оригинала у автора в высоком разрешении (для СМИ, авиакомпаний или печати), Защита от хотлинкинга и правого клика мыши / сохранения

14. **[Вопрос 14/150] Нужна ли геймификация и система рейтингов для фотографий («Фото дня», «Топ недели»)?**
    - **Ответ:** (Recommended) Полноценный рейтинг: «Фото дня», «Фото недели», топ авторов, выбор редакции и выбор сообщества

15. **[Вопрос 15/150] Какие дополнительные медиа-форматы планируется поддерживать в медиатеке?**
    - **Ответ:** Видео споттинга (встраивание YouTube/Vimeo + загрузка коротких вертикальных клипов/Shorts), Аудиозаписи переговоров пилотов с диспетчерами (LiveATC/радиообмен), привязанные к бортам/аэропортам, Интерактивные 360-градусные панорамы кабин и салонов

16. **[Вопрос 16/150] Какой источник данных планируется использовать для интерактивного радара полетов?**

    - **Ответ:** 2D и 3D отображение трека полета, текущей высоты, скорости и вертикальной скорости, Фильтры на карте (по типам ВС, авиакомпаниям, высоте, аэропортам вылета/прилета), Погодные слои (METAR, зоны гроз и осадков, ветер на эшелонах, турбулентность), Аэронавигационные слои (воздушные трассы/airways, навигационные точки/waypoints, секторы УВД)

20. **[Вопрос 20/150] Нужна ли функция воспроизведения истории полетов (Playback / Архив треков)?**

    - **Ответ:** Каталог ливрей (liveries) и модификаций для MSFS, X-Plane, DCS с фильтрами по моделям, Интеграция с онлайн-сетями VATSIM / IVAO / POSCON (карта активных диспетчеров и бортов онлайн), Планировщик полетов и расчет топлива/маршрута (расчет ветра, эшелона, путевых точек), Электронные чек-листы (Checklists), QRH и стандартные операционные процедуры (SOP) для ВС

22. **[Вопрос 22/150] Нужна ли встроенная система Виртуальной Авиакомпании (Virtual Airline / ВАК)?**
    - **Ответ:** (Recommended) Полноценная платформа виртуальных авиакомпаний (ВАК): учет налета, карьера пилота, назначение рейсов

23. **[Вопрос 23/150] Как будет организовано скачивание ливрей, модов и утилит для авиасимуляторов?**

24. **[Вопрос 24/150] Какой формат обучения и гайдов (Flight Training) должен присутствовать на сайте?**
    - **Ответ:** Интерактивная «Лётная школа»: пошаговые уроки от базового пилотирования до полетов по приборам (IFR/VFR), Разборы аэронавигационных карт (Jeppesen / AIP) и схем захода (SID/STAR, ILS, RNAV), Гайды по авионике (Garmin G1000/G3000, FMC/MCDU Boeing и Airbus), Тесты и викторины для проверки знаний авиационных правил и процедур

25. **[Вопрос 25/150] Нужна ли интеграция с сервисом SimBrief для импорта и построения планов полета (OFP)?**
    - **Ответ:** Нет, пусть пользователи пользуются SimBrief отдельно

### Блок 60: Realtime Streaming Архитектура — SSE + WebSocket (Вопросы 316–320)

316. **[Вопрос 316/320] Какой протокол реального времени используется для AI-ответов (стриминг)?**
      - **Ответ:** **SSE (Server-Sent Events)** — основной протокол для AI-стриминга:
        - Нативный HTML/JS API `EventSource` для потребления SSE в браузере
        - HTTP/1.1 или HTTP/2, работает через стандартные Nginx/Caddy
        - Формат событий: `data: {json}\n\n` с типами событий:
          - `reasoning:start` — начало цепочки рассуждений (для reasoning-моделей)
          - `reasoning:chunk` — фрагмент цепочки рассуждений
          - `reasoning:end` — завершение цепочки рассуждений
          - `response:start` — начало финального ответа
          - `response:chunk` — фрагмент финального ответа (посимвольный вывод)
          - `response:end` — завершение ответа
          - `tool_call:start` — начало вызова инструмента
          - `tool_call:result` — результат вызова инструмента
          - `error` — ошибка с кодом и сообщением
        - Автоматическое восстановление соединения при обрыве
        - Анимация курсора печати на фронтенде
        - PHP-реализация: headers `Content-Type: text/event-stream`, `Cache-Control: no-cache`, `Connection: keep-alive`

317. **[Вопрос 317/320] Какой протокол реального времени используется для чата и радара?**
      - **Ответ:** **WebSocket** — для двунаправленной связи:
        - Чат ИИ: отправка сообщений, прикрепление файлов, управление сессиями
        - Радар: обновление позиций самолетов в реальном времени (каждые 5-10 сек), слои погоды, фильтры
        - LiveATC: управление аудиоплеером (play/pause, переключение частот)
        - Уведомления: push-уведомления в реальном времени
        - Реализация на PHP: Ratchet PHP или чистый WebSocket сервер через ReactPHP/Swoole
        - Альтернатива для shared хостинга: long-polling как fallback при невозможности WebSocket

318. **[Вопрос 318/320] Как реализовано SSE streaming в PHP на shared хостинге?**
      - **Ответ:** Реализация:
        - PHP-скрипт `sse_stream.php` принимает POST с параметрами (prompt, model, api_key)
        - Устанавливает заголовки SSE, блокирующий буфер вывода
        - Посимвольно выводит данные по мере получения из LLM через cURL (streaming read)
        - Каждый фрагмент отправляется через `echo` + `flush()` + `ob_flush()`
        - Для reasoning-моделей: отдельный stream для reasoning block + отдельный для response
        - Работает на любом shared хостинге с PHP 8.x + cURL
        - Timeout: увеличен до 120 сек для длинных ответов
